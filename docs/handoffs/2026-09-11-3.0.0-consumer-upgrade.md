**Date:** 2026-09-11
**Status:** Prepared. Tags not yet cut. Supersedes the

Strategos moves **3.0.0-rc.1 → 3.0.0** and `LevelUp.Strategos.Contracts` moves
**0.12.0 → 0.13.0**. A consumer that skipped the pre-release moves 2.10.0 → 3.0.0

This file records only the delta since rc.1, and what each already-filed adoption
issue now needs.

## What GA adds over rc.1

Four programs, three of which close a place where two runtimes could disagree about
one contract.

1. **An action contract crosses an assembly boundary (#204).** A project that
   declares a `BoundToWorkflow` action exports its contracts as a `ProofCatalogV1`
   document on an assembly-level attribute and defers the binding; the compilation
   that lowers the workflow imports and merges it, then discharges the binding with
   the code that proves a local one. Before this, a binding was provable only in the
   compilation that declared it — which forced the ontology and the workflow into one
   project. New refusals: `AGWF046` (contract not projectable into the portable
   form), `AGWF047` (referenced catalog unreadable — refused, never skipped),
   `AGWF048` (two catalogs claim one ordinal identity, no tie-break by design), and
   `AONT222` (a binding declared by a project with nothing to export it).
2. **The workflow-definition kernel is frozen (#193, #209).** `contentHash`, the
   `authority` frame, and the reserved composition-combinator `kind` values enter
   `WorkflowDefinitionV1` as **carried, not proved** slots. Nothing in the lowering
   path reads them in 3.0. Freezing the names now makes the later behavior an
   additive minor rather than a breaking kernel change.
3. **Strategos emits the Zod/TypeScript projection (#219).** `Generated/zod/` is now
   emitted from the same TypeSpec sources as the C# records and the JSON Schema. See
   *Exarchos* below — this is the largest change in this notice for a single consumer.
4. **Closed-enum wire slots are enforced on import (#221).** `AGWF049`. See
   *The one way a document that built clean can now fail*.

## Release order — unchanged mechanism, new versions

The order and the reasons are exactly as the rc.1 notice states. Only the versions
move:

1. **Tag `contracts-v0.13.0` first.** `publish-contracts.yml` gates it on the tag
   equalling the pinned `<ContractsVersion>` (`0.13.0`), a clean regenerate-and-diff,
   the breaking-change diff against the newest stable on nuget.org (now **0.12.0**,
   published 2026-09-09 — not 0.4.0 as at rc.1), and the >= 100-case builder-fixture
   corpus.
2. **Verify 0.13.0 is live on the nuget flatcontainer index before step 3.** The
   product nuspec depends on the pinned Contracts version; the product cannot be
   pushed against a version the feed does not yet carry.
3. **Then tag `v3.0.0`.** `publish.yml` versions with MinVer from the tag. The tag
   has no hyphen, so this publishes as a stable release, not a pre-release.

## Consumer-first rule, restated for 0.13.0

The generated `AgwfCode` enum throws on a member it does not know. 0.13.0 adds
`AGWF046`–`AGWF049`. A consumer on 0.12.0 cannot deserialize a payload carrying any
of them. **Consumers restore 0.13.0 before any producer on 3.0.0 emits diagnostics or
workflow definitions to them.** This is the same rule the rc.1 notice states for
`AGWF035`–`AGWF045`; it has not relaxed.

## The one way a document that built clean can now fail

Four slots in a `.workflow.json` are typed by a closed contract enum:
`gates[].class`, `steps[].runtime`, a failure handler's `scope`, and a permitted fork
trigger. Through 2.10 the .NET import front-end read all four as opaque strings and
accepted any token, while the emitted TypeScript arm rejected anything outside the
enum. From 3.0 both arms agree: an unknown token is `AGWF049`, naming the file, the
construct, the JSON path, and the full vocabulary.

Two spellings account for nearly every case:

- a **member name where its wire value belongs** — `"Typecheck"` for `"typecheck"`,
  `"RatificationFailure"` for `"ratification_failure"`. Consumers round-trip these by
  value, never by member name;
- a **class retired by an earlier contract major** — `"AntipatternDetection"` predates
  0.4.0 and has no successor token; a deterministic rule set is `"rules"`.

This repository's own corpus carried both spellings — twelve declarations across two
test files, live for four minors and caught only when the gate was turned on. A
consumer with hand-authored workflow JSON should expect the same and sweep before
upgrading.

| `lvlup-sw/valkyrie` | Ontology-only; the GA delta is `AONT222` — if any valkyrie project declares a `BoundToWorkflow` action while referencing only `LevelUp.Strategos.Ontology`, it must add the generator package. Otherwise unchanged from the rc.1 notice. |

## Verification the maintainer can run after a consumer lands

Everything in the rc.1 notice, plus:

- `dotnet restore` resolves exactly one `LevelUp.Strategos.Contracts` version
  (0.13.0) across every `project.assets.json`.
- A consumer-side deserialization test round-trips an `AgwfCode` of `AGWF049` without
  throwing.
- For a consumer that splits ontology and workflows: the producing project emits a
  proof catalog and the consuming project's build discharges the binding — a build
  with `<StrategosProofRequireLocalBindings>true</StrategosProofRequireLocalBindings>`
  set in the **host only**, never in a library.
- A sweep of every hand-authored `.workflow.json` for out-of-vocabulary closed-enum
  tokens, before the 3.0 build starts.

## Not swept

- Whether any consumer hand-authors `.workflow.json` outside its test corpus. The
  `AGWF049` exposure above is stated as a risk, not as a measured finding.
- Whether exarchos's `contract-authority.lock.json` mechanism can pin a generated
  artifact from another repository without a publication channel for it. Strategos
  commits `Generated/zod/` but does not publish it as an npm package.
