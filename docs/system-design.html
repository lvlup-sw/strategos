Strategos — system design
the compiler checks the composition.

Strategos is a declarative contract layer with a compiled durable runtime. You describe a workflow with a fluent DSL (or ship its wire IR as *.workflow.json), describe your domain as an ontology, and describe what each action may do as a typed contract. A Roslyn source generator lowers the workflow into a Wolverine saga persisted by Marten; analyzers prove the ontology and the action calculus before anything runs; a TypeSpec spine publishes the shared shapes to basileus, exarchos, valkyrie and dynatoi. Every diagram below states one claim and names the files it was read from — the compiler checks the composition, so the runtime only has to be durable.

01 · the packages

Package map

Fourteen packages ship from one repository on two publish lines: thirteen product packages versioned by MinVer from the v* tag, and LevelUp.Strategos.Contracts pinned to its own contracts-v* tag. Every solid edge below is a ProjectReference read from src/*/*.csproj; dotted edges are <Compile Include … Link> source links or a pack-time bundling. Nothing is inferred from names.

02 · the compiler

Compile pipeline

A workflow enters the compiler one of two ways and leaves it one way. Front-end A is a [Workflow] class whose Definition is a fluent chain — Workflow<TState>.Create("name").StartWith<T>().Then<T>().Branch(…).Fork(…).Join<T>().RepeatUntil(…).AwaitApproval<T>().OnFailure(…).Finally<T>(). Front-end B is a *.workflow.json AdditionalFile carrying WorkflowDefinitionV1 wire IR. Both lower into the same WorkflowModel, and WorkflowIncrementalGenerator.EmitWorkflowSources is the only path out (U-1).

03 · the runtime

Runtime lifecycle

At runtime a workflow instance is one Wolverine saga document in Marten. Nothing here is hand-written: the saga class, its Handle overloads, the worker handlers and the DI registration all come out of the compiler above. Your code is the IWorkflowStep<TState> implementations and the immutable state record.

04 · the ontology

Ontology layer

The ontology is a semantic type system agents plan and act against. It is architecturally independent of the workflow DSL: the Ontology package has no project references, is validated by Roslyn analyzers rather than generators, and exposes itself to agents through MCP tools that carry the graph's version in every reply.

05 · the calculus

Action calculus proof flow

An ontology action is an immutable state-transition contract, and Strategos proves whether one action may follow another instead of parsing display strings. The proof is exact and decidable because the predicate language is closed; what it cannot see is stated on the diagram, not hidden.

06 · the spine

Contracts spine and consumers

TypeSpec is the single canonical source of every cross-product shape. The build emits C# records for .NET consumers and JSON Schema for everyone else, packs both into an independently versioned NuGet, and publishes it before the product packages that depend on it.
