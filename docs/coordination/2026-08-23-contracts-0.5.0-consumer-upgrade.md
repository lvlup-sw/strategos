# Contracts 0.5.0 consumer-upgrade notice — the `AGWF035` diagnostic code

**Date:** 2026-08-23
**Status:** Consumer set verified 2026-08-23; the one real consumer is notified.

`LevelUp.Strategos.Contracts` moves **0.4.0 → 0.5.0**, adding one AGWF diagnostic
code: `UnreachableTermination` / `AGWF035`.

The addition is schema-additive (a new enum member and a new catalog entry), so it
is a minor bump — but the **upgrade sequences consumer-first**. `AgwfCode` carries
`[JsonConverter(typeof(JsonStringEnumConverter<AgwfCode>))]` with per-member
`[JsonStringEnumMemberName("AGWF0xx")]`, so it round-trips by *name* and the
converter throws on a member it does not know. A consumer still pinned to 0.4.0
cannot deserialize a payload carrying `AGWF035`.

### A stale claim this surfaced

`AgwfCode`'s generated XML doc asserts that its member names are *"the stable
contract Exarchos's TypeScript enum round-trips against by name (not ordinal —
INV-5)"*. **No such enum exists in exarchos today** — three independent code
searches (`AgwfCode`, `AGWF035`, `agwf`) return nothing on an indexed repository
whose other Strategos references do resolve. The prose describes an intended seam,
not a live one. It is generated from `Diagnostics/AgwfCatalog.tsp`, so correcting
it is a source-side edit, deliberately left out of this release's scope.

The consequence for sequencing is favourable: with exarchos carrying no AGWF
surface, `AGWF035` has exactly one deserializing consumer to get ahead of.

## Issue filed

**lvlup-sw/basileus#489** — *Bump LevelUp.Strategos.Contracts to 0.5.0 alongside the
Strategos 2.11.0 upgrade*.

Note the framing shifted once basileus was actually read. The deserialization hazard
above is **latent, not live**: basileus references AGWF codes only in prose ADRs and
never binds `AgwfCode` in code. Its concrete obligation is *version unification* —
`Directory.Packages.props:20` pins Contracts directly at `0.4.0` because the 2.9.1
Strategos line drags `0.3.0` transitively and transitive pinning is off. Strategos
2.11.0 drags `0.5.0`, so taking that bump without moving the direct pin splits the
graph, and `GateClassSourceTests` (which reads every `project.assets.json` and fails
on a non-singleton union) goes red. The two bumps must move in one commit.
