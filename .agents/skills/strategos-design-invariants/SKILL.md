# Strategos Design Invariants

Audits a design proposal or diff against Strategos-specific architectural invariants. Project-scoped — these invariants govern Strategos itself, not consumers of it.

## Project framing

> Fluent DSL for building durable agentic workflows and ontologies in .NET.

This sentence governs every invariant below. When a candidate constraint doesn't follow from this characterization, the framing rejects it.

## When to use

- During design (`/exarchos:ideate`, RFC drafting), before committing.
- During review (`/exarchos:review`), alongside `/axiom:audit`.
- When reviewing a PR that touches the workflow DSL/builder surface (`src/Strategos/`), the Roslyn generators (`src/Strategos.Generators/`), the ontology descriptor model (`src/Strategos.Ontology/`), or the MCP protocol layer (`src/Strategos.Ontology.MCP/`).

## When NOT to use

- For generic backend quality — use `/axiom:*` skills.
- For TDD / spec compliance — use the workflow's `review` skill.
