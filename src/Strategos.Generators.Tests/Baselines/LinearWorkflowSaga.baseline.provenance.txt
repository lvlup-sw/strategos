Provenance for LinearWorkflowSaga.baseline.txt
==============================================

WHAT IT IS
  The complete non-event-sourced (SagaDocument) saga emit for a linear workflow —
  no fork, no branch, no loop, no failure handler, no approval point, no
  confidence gate.

  It is the "before" half of the linear-workflow output-equality guard: any
  later change to the generator that is supposed to be inert for a workflow
  with no off-main-flow steps must leave this file byte-identical. Writing the
  expectation after such a change instead would embed post-change output and be
  green by construction.

HOW IT WAS CAPTURED
  Fixture      : SourceTexts.LinearWorkflow
                 (StartWith<ValidateOrder> -> Then<ProcessPayment>
                  -> Finally<SendConfirmation>, persistence mode SagaDocument)
  Emit         : hint name "ProcessOrderSaga.g.cs" from
                 GeneratorTestHelper.RunGenerator(SourceTexts.LinearWorkflow)
  Verified     : LinearWorkflowSaga_RepeatedGeneratorRuns_ProduceIdenticalOutput
                 asserts run-to-run byte equality, so a mismatch here is always
                 attributable to a change and never to generator nondeterminism.

WHY IT WAS RE-CAPTURED (supersedes the 2026-08-22 capture)
  Re-capture reason (b) of the previous provenance note: linear output changed
  deliberately, for a reason unrelated to off-main-flow classification or
  step-list ordering.

  The previous baseline was captured at 92e3e676a0f8a8cc6ea08f994fb740b885743471
  (2026-08-22) as the "before" for the off-main-flow classification and
  step-list reordering work. That work has landed and this file matched it
  byte-for-byte, so the inertness claim it existed to falsify is discharged.

  The change that forced the re-capture is the saga concurrency fix. It alters
  the linear emit in exactly four places, all of them intended and all of them
  visible in the diff against the previous baseline:

    1. `using Marten.Schema;` is dropped. It existed solely to bring
       Marten's [Version] attribute into scope.
    2. `using Wolverine.ErrorHandling;` and `using Wolverine.Runtime.Handlers;`
       are added, for the emitted error policy.
    3. The `[Version] public new long Version { get; set; }` property is gone,
       and the class declaration gains `, JasperFx.IRevisioned`. The shadow
       property satisfied Marten's document mapping but NOT the
       `CanBeCastTo<JasperFx.IRevisioned>` test in
       Wolverine.Marten.Persistence.Sagas.MartenPersistenceFrameProvider
       .DetermineUpdateFrame, so Wolverine emitted a plain
       `documentSession.Update(saga)` and concurrent saga transitions were
       last-write-wins. The interface is implemented by the inherited
       `Wolverine.Saga.Version` (int), which Marten's default VersionedPolicy
       maps to numeric revisions with no attribute needed.
    4. A `public static void Configure(HandlerChain chain)` is added, applying
       `chain.OnException<JasperFx.ConcurrencyException>().RetryTimes(3)`.
       Wolverine has no default rule for ConcurrencyException, so without it the
       first lost race dead-letters immediately.

  Nothing else in the emit moved.

THE ONE NORMALIZATION
  The emitted [GeneratedCode("LevelUp.Strategos", "<version>")] argument is
  resolved from the generator assembly's MinVer-stamped informational version
  (Helpers/GeneratorMetadata.cs), so it changes with every commit's height even
  when no generator source changes at all. A literally byte-identical baseline
  would therefore fail on the next commit for a reason that has nothing to do
  with the emit.

  That single token — and nothing else — is stored here as the placeholder
  {generator-version}, and the comparison applies the identical substitution to
  the regenerated output before comparing. Line endings are normalized to LF on
  both sides. Every other byte is compared exactly.

RE-CAPTURING
  Do NOT re-capture this file to make a failing comparison pass.

  A difference against this baseline means one of two things, and only reading
  the diff tells you which:
    (a) a change that was supposed to be inert for a linear workflow leaked into
        its output — fix the change, not the baseline; or
    (b) linear output changed deliberately for a stated reason — in which case
        re-capture, and replace this whole file with the new provenance and the
        reason, as was done here.
